# 😴 ANTI MICROSLEEP — ระบบตรวจจับคนขับง่วง (Arduino UNO Q)

ระบบตรวจจับอาการง่วงและหลับในของคนขับรถ สำหรับพนักงานขับรถส่งของ
ใช้กล้อง USB ดูใบหน้าแบบเรียลไทม์บนบอร์ด **Arduino UNO Q** ถ้าคนขับหลับตา ก้มหัว หรือหัวตก
ระบบจะส่งเสียงเตือน (beep.wav) และแสดงสถานะบนไฟ LED, LED matrix และหน้าเว็บสด

> ทุกอย่างประมวลผล **บนบอร์ด** ไม่ต้องใช้อินเทอร์เน็ต
> (ยกเว้นโมเดล Roboflow ซึ่งเป็นตัวเสริม ไม่บังคับใช้)

## 1. ฮาร์ดแวร์

| อุปกรณ์ | หมายเหตุ |
|---|---|
| **Arduino UNO Q** | Linux (Qualcomm QRB2210, Cortex-A53) + MCU (STM32U585) |
| **กล้อง USB** (ทดสอบกับ Signo WB-400) | ติดตั้ง **ตรงหน้าคนขับ** เช่น บนแผงหน้าปัดเหนือพวงมาลัย |
| **USB-C hub ที่มีช่องจ่ายไฟ PD** | บอร์ดมีช่อง USB-C ช่องเดียว ต้องใช้ hub เพื่อต่อกล้อง |
| **หัวชาร์จ USB-C PD ≥ 20W (5V 3A)** | ⚠️ ห้ามใช้พอร์ต USB ของคอม ไฟไม่พอ กล้องจะหลุดและภาพแตก |
| ลำโพง USB *(ตัวเลือก)* | เล่น `sounds/beep.wav` ตอนเตือนระดับแดง |
| Buzzer / ลำโพง + แอมป์ (PAM8403) ที่ขา **D9** *(ตัวเลือก)* | เสียง 988 Hz ระดับเดียวกับ beep.wav ไม่ขึ้นกับ Linux |

**ในรถจริง:** ใช้ที่ชาร์จในรถ (12V/24V) แบบ **USB-C PD ≥ 30W (5V 3A ขึ้นไป)** ต่อผ่านช่อง PD-in ของ USB-C hub เท่านั้น
⚠️ ห้ามต่อไฟรถบรรทุก 24V (ซึ่งขณะเครื่องติดอาจสูงถึง 27–28V) เข้าขา VIN โดยตรง และห้ามจ่ายเกิน 5V เข้าทาง USB หรือขา 5V

## 2. ระบบทำงานอย่างไร

```
กล้อง USB (640x480, 15 fps)
   │
   ▼
[Linux / Python]  python/main.py
   ├─ face_engine.py : หาใบหน้า (BlazeFace) + วางจุด 478 จุด (Face Mesh)  ← AI บนบอร์ด (LiteRT)
   ├─ EAR  : ตาเปิด/หรี่/ปิด   (ความสูงตา ÷ ความกว้างตา)
   ├─ ตรวจตาดำ : แยก "หรี่ตา" ออกจาก "หลับตา"
   ├─ MAR  : หาว / ความกว้างปาก : ยิ้ม-หัวเราะ
   ├─ Head pose (solvePnP) : ก้มหัว / เอียงหัว / หันออก
   ├─ PERCLOS : % เวลาตาปิดใน 60 วินาที
   ├─ YOLOX (Object Detection brick) : มีคนอยู่หน้ากล้องแต่ไม่เห็นหน้า = หัวฟุบ  ← AI บนบอร์ด
   ├─ Roboflow (ตัวเสริม, cloud) : ความเห็นที่สองเรื่องตาเปิด/ปิด
   ├─ เรียนรู้ค่าปกติของคนขับเองอัตโนมัติ (ไม่ต้องปรับเกณฑ์)
   └─ ตัดสินระดับเตือน 0/1/2
        │ Bridge (RPC)                 │ USB speaker
        ▼                              ▼
[MCU / sketch.ino]                  beep.wav (เฉพาะสีแดง)
   LED4, LED matrix, เสียง 988 Hz ขา D9
```

### ทำไมไม่ใช้แพ็กเกจ `mediapipe`
แพ็กเกจ `mediapipe` สำหรับ ARM64 ต้องใช้ CPU รุ่น ARMv8.2 ขึ้นไป แต่ Cortex-A53 ของ UNO Q เป็น ARMv8.0
จึงแครชทันที (SIGILL) โปรเจกต์นี้เลยนำ **โมเดลชุดเดียวกัน** (`face_landmarker.task`) มารันผ่าน **LiteRT** แทน
ได้ความเร็วประมาณ 30 ms ต่อเฟรม

### การเรียนรู้อัตโนมัติ (ไม่มีขั้นตอนปรับเกณฑ์)
ระบบเรียนรู้ค่าปกติของคนขับแต่ละคนจากเฟรมที่หน้าตรง ย้อนหลัง 2 นาที:
- **ตา:** ค่า EAR ตอนลืมตา (เปอร์เซ็นไทล์ที่ 75) แล้วตั้งเกณฑ์หลับตา = 45% และช่วงหรี่ตา = 45–65%
- **ศีรษะ:** มุมก้มและมุมเอียงปกติ (กล้องอาจติดเอียง)
- **ปาก:** ความกว้างปากปกติ (ใช้แยกการยิ้มหรือหัวเราะ)
- ค่าเกณฑ์ **ลดลงได้ช้ามาก** (0.03/นาที) เพื่อไม่ให้ระบบปรับตามตาที่หรี่ลงเพราะง่วง
- ถ้าไม่เห็นหน้าเกิน 30 วินาที (เช่น เปลี่ยนคนขับ) ระบบจะเริ่มเรียนรู้ใหม่

## 3. ระดับการเตือน

| สี | ความหมาย | เสียง |
|---|---|---|
| 🟢 ปกติ | ตื่นดี | — |
| 🟡 เตือน | มีอาการง่วง หรือไม่มองถนน | ❌ ไม่มีเสียง (ไฟอย่างเดียว) |
| 🔴 อันตราย | หลับใน | ✅ beep.wav (ลำโพง USB) + 988 Hz (ขา D9) |

### กฎการเตือน

| เหตุการณ์ | 🟡 เตือน | 🔴 อันตราย |
|---|---|---|
| หลับตาต่อเนื่อง | ≥ 1 วิ | ≥ 2 วิ |
| ตาปิด ≥ 80% ใน 2 วิล่าสุด (กันค่ากระพริบ) | — | ทันที |
| ก้ม/เอียงหัว + ตาปิด ≥ 50% ใน 2 วิ | — | หลังก้ม 1.5 วิ |
| ก้มหัว > 18° หรือเอียง > 25° | ≥ 2 วิ | ≥ 5 วิ |
| หัวตกจนไม่เห็นหน้า | ≥ 1 วิ | ≥ 3 วิ |
| มีคนอยู่หน้ากล้อง แต่ไม่เห็นหน้า (YOLOX) | ≥ 1 วิ | ≥ 3 วิ |
| ตาแคบ (หรี่/ปิด) ต่อเนื่อง "ตาหนัก" | ≥ 4 วิ | — |
| PERCLOS (ตาปิดใน 60 วิ) | ≥ 20% | — (≥ 35% = "ง่วงมาก" แต่ยังเป็นสีเหลือง) |
| หาว | ≥ 3 ครั้งใน 5 นาที | — |
| หันหน้าออก (ไม่มองถนน) | ≥ 4 วิ | — |
| ไม่เห็นหน้า (ไม่มีคน) | ≥ 4 วิ | — |

**ไม่นับว่าหลับตา:**
- **หรี่ตา** (ยังเห็นตาดำตรงกลางตา) → ขอบตาสีส้มบนหน้าเว็บ
- **ยิ้ม / หัวเราะ** (ปากกว้างกว่าปกติ ≥ 10%)
- ยกเว้นตอน **ก้มหรือเอียงหัว**: ตาแคบในช่วงนั้นนับเป็นหลับตาทันที

**อื่น ๆ:**
- สีแดงค้างอย่างน้อย 1.5 วินาที (กันไฟกระพริบ)
- การหลับตา 1 ครั้งนับเข้า PERCLOS ได้สูงสุด 1 วินาที (หลับตานานแล้วลืมตา จะไม่เตือนค้างอีก 1 นาที)

### ไฟ LED4 บนบอร์ด
| สี | ความหมาย |
|---|---|
| 🟢 เขียว | ปกติ |
| 🟡 เหลือง | เตือน |
| 🔴 แดงกะพริบ + LED matrix กะพริบ | อันตราย |
| 🔵 น้ำเงินกะพริบ | ไม่พบกล้อง |
| 🔵 น้ำเงินค้าง | ไม่เห็นหน้า |
| 🟣 ม่วง | มืดเกินไป |
| ⚪ ขาวกะพริบ | ฝั่ง Python ไม่ทำงาน (ไม่ได้รับข้อมูล 3 วิ) |

## 5. ติดตั้งและใช้งาน

### ติดตั้งครั้งแรก
1. เปิด **Arduino App Lab** → สร้างแอปใหม่ (หรือใช้แอป `ANTI MICROSLEEP` เดิม)
2. คัดลอกไฟล์ทั้งหมดในโฟลเดอร์นี้ไปไว้ในแอป
   - หรือคัดลอกผ่าน SSH: `scp -r anti-microsleep/* arduino@<IP บอร์ด>:~/ArduinoApps/anti-microsleep/`
3. ต่อ **กล้องผ่าน USB-C hub** และ **เสียบหัวชาร์จ PD ≥ 20W** เข้า hub **ก่อน**กด Run
4. กด **Run** ใน App Lab
   - ครั้งแรกจะติดตั้ง `ai-edge-litert` และดาวน์โหลดโมเดลใบหน้า (ต้องมีอินเทอร์เน็ต)

### ใช้งานทุกครั้ง
1. เปิดแอป (Run)
2. นั่ง **หันหน้าตรงเข้ากล้อง** ตามปกติ ระบบจะเรียนรู้ตาและท่าทางเองภายในประมาณ 20–30 วินาที
3. ดูสถานะบนไฟ LED4 หรือหน้าเว็บ

### คำสั่งที่ใช้บ่อย (ผ่าน SSH)
```bash
arduino-app-cli app stop user:anti-microsleep
arduino-app-cli app start user:anti-microsleep
docker logs --tail 50 anti-microsleep-main-1
```

## 6. หน้าเว็บดูสด (Live view)

เปิด **`http://<IP บอร์ด>:7000`** จาก PC หรือมือถือที่ต่อ Wi-Fi วงเดียวกัน

- ภาพจากกล้องพร้อมจุดบนใบหน้า ขอบตา **ฟ้า = ลืมตา, ส้ม = หรี่ตา, แดง = หลับตา**
- สถานะและเหตุผลที่เตือน
- กราฟ EAR 30 วินาที พร้อมเส้นเกณฑ์
- PERCLOS, หาว, ความสว่าง, FPS, ทิศหันหน้า, มุมก้ม/เอียงหัว, สถานะ AI
- ปุ่ม **รีเซ็ต**: ล้าง PERCLOS และเริ่มเรียนรู้ตาใหม่
- ช่องใส่ **Roboflow API key**
- ถ้าแอปรีสตาร์ท หน้าเว็บจะต่อวิดีโอใหม่เอง

#### 🔒 รหัสผ่านหน้าดูสด
หน้านี้มีภาพหน้าคนขับ จึงต้องล็อกอินก่อน (ภาพสด, สถิติ, ปุ่มรีเซ็ต, Roboflow key) — หน้า `driver.html` ไม่ต้องใช้รหัส
- **ครั้งแรก** ที่แอปเริ่ม จะสร้างรหัสสุ่ม 8 ตัว ดูได้ด้วย
  `cat ~/ArduinoApps/anti-microsleep/live_password_initial.txt`
  (หรือ `docker logs anti-microsleep-main-1 | grep "Live page password"`)
- เปลี่ยนรหัสได้ที่การ์ด **เปลี่ยนรหัสผ่านหน้านี้** บนหน้าเว็บ (ไฟล์รหัสเริ่มต้นจะถูกลบ และเครื่องอื่นต้องล็อกอินใหม่)
- **ลืมรหัส / ตั้งรหัสผ่าน SSH:** `echo 'รหัสใหม่' > ~/ArduinoApps/anti-microsleep/live_password.txt` แล้วรีสตาร์ทแอป — ไฟล์นี้จะถูกลบเองหลังอ่าน
- ล็อกอินค้างไว้ 30 วัน (คุกกี้) · ใส่ผิด 5 ครั้งติดกันล็อก 60 วินาที · บนบอร์ดเก็บแค่ค่า hash (`live_auth.json`)
- ข้อจำกัด: ยังเป็น HTTP ธรรมดา คนที่ดักฟัง Wi‑Fi เดียวกันได้ยังเห็นรหัส/วิดีโอได้ — ถ้าจะใช้ผ่านอินเทอร์เน็ตต้องทำ HTTPS ก่อน

### หน้าเว็บคนขับ (แผนที่เป็นหน้าหลัก)
เปิด **`http://antims.local:7000/driver.html`** (หรือ `http://<IP บอร์ด>:7000/driver.html`)
- **แผนที่เต็มจอ** ตำแหน่งรถ (GPS) + จุดพักใกล้ ๆ
- เลือก **⛽ ปั๊มน้ำมัน / 🅿️ จุดพักรถ / ☕ ร้านกาแฟ** → บอกที่ใกล้ที่สุด (เลือกที่อยู่ **ข้างหน้า** ก่อน) + ระยะทาง
  - ระยะ **ตามถนน** เมื่อมีเครื่องคำนวณเส้นทาง (OSRM) บนบอร์ด ไม่งั้นเป็นเส้นตรง
- ปุ่ม **🧭 นำทาง** เปิด Google Maps พร้อมจุดหมาย
- สถานะ 🟢🟡🔴 ด้านล่าง ขอบจอกะพริบแดงเมื่ออันตราย และสลับไปแสดง **จุดพักรถ** อัตโนมัติเมื่อง่วง
- เวลาขับ / เตือนพักทุก 2 ชม. / การเตือนวันนี้ (กด "เวลาขับ · การเตือนวันนี้")
- ยังไม่มี GPS → ใช้ **ตำแหน่งทดสอบ** (กดค้างบนแผนที่เพื่อย้าย)

ข้อมูลจุดพัก: `maps/pois.json` จาก OpenStreetMap (ปั๊ม 8,724 · จุดพัก 1,624 · ร้านกาแฟ 12,266)
สร้างใหม่ด้วย `tools/extract_pois.py` จากไฟล์ `thailand-latest.osm.pbf` (Geofabrik)

**แผนที่ออฟไลน์** `maps/thailand.pmtiles` (461 MB, ทั้งประเทศ zoom 14, Protomaps)
- สร้างด้วย `tools/get_offline_map.sh` (ใช้เครื่องมือ `pmtiles` ของ Protomaps)
- ถ้าไม่มีไฟล์นี้ หน้าเว็บจะใช้แผนที่ออนไลน์ (ต้องมีสัญญาณ)

**ระยะทางตามถนน (OSRM, ออฟไลน์)**
- ข้อมูลถนน `~/osm/osrm/` (457 MB) สร้างด้วย `tools/osrm_build.sh lighter`
  - ใช้ถนนหลัก/รอง/ถนนเชื่อม **ไม่รวมซอยในหมู่บ้าน** เพราะ RAM บอร์ดไม่พอสำหรับทั้งประเทศ (ใช้ RAM ~2.5 GB ตอนสร้างแล้วโดนตัด)
  - ตอนสร้างจะหยุดแอปชั่วคราว (~10 นาที) แล้วเปิดใหม่เอง
- รันเป็น container `osrm` พอร์ต 5000 เปิดเองเมื่อบอร์ดเปิด (`tools/osrm_service.sh`) ใช้ RAM ~300 MB
- ถ้า OSRM ไม่ทำงาน หน้าเว็บจะแสดงระยะเส้นตรงแทน

### GPS (NEO-6M / NEO-M8N)
| GPS | UNO Q |
|---|---|
| VCC | 3.3V |
| GND | GND |
| TX | D0 (RX, `Serial1`) |
| RX | D1 (TX) ไม่บังคับ |

9600 baud, MCU ส่งตำแหน่งให้ Python ทุก 1 วิ (`Bridge.notify("gps", ...)`) ให้เสาอากาศมองเห็นท้องฟ้า (ใกล้กระจกหน้า)

### เครือข่ายและการเปิดเอง
- แอปตั้งเป็น **default app** → เปิดเองเมื่อบอร์ดเปิด (`arduino-app-cli properties set default user:anti-microsleep`)
- ชื่อบอร์ด `antims` → `antims.local`
- บันทึกฮอตสปอตคนขับ `AMS` ไว้ (priority 10) และ Wi‑Fi บ้าน/ศูนย์ไว้สำหรับอัปเดตโค้ด

## 7. โมเดล AI Roboflow (ตัวเสริม)

โมเดล `eye_close_project/2` (คลาส `closed eye`, `Drowsy`) ใช้เป็น **ความเห็นที่สอง**:
- ทำได้แค่ **ยกเลิก** การนับตาปิดที่น่าจะผิด (มั่นใจ ≥ 70% ว่าตาเปิด) แต่ **เพิ่มการนับตาปิดเองไม่ได้**
  เพราะจากการทดสอบ โมเดลนี้นับการหรี่ตาว่าเป็น "closed eye"
- ตาที่ปิดสนิทชัดเจน AI ยกเลิกไม่ได้ เพื่อความปลอดภัย
- ส่งเฉพาะภาพใบหน้าขนาด 256 px ทุก 3 วิ (ทุก 0.7 วิตอนตาปิด) ผ่านการเชื่อมต่อ HTTPS ที่เปิดค้างไว้ → **~0.3 วิ/ครั้ง**
- ไม่มีเน็ตหรือไม่มี key → ระบบทำงานด้วย EAR อย่างเดียวตามปกติ

**ใส่ API key:** หน้าเว็บ → กล่อง "Roboflow API key" → วาง Private API Key → บันทึก
(หรือสร้างไฟล์ `roboflow_api_key.txt` ข้าง `app.yaml`)

⚠️ ภาพใบหน้าคนขับจะถูกส่งไปที่เซิร์ฟเวอร์ Roboflow ควรแจ้งคนขับ ใช้เน็ตประมาณ 20–40 MB/ชม. และมีค่าใช้จ่ายตามโควตา

## 10. ข้อจำกัดและงานต่อไป

**ข้อจำกัดตอนนี้**
- กล้องธรรมดาใช้ไม่ได้ในที่มืด (ไม่มี IR) → ไฟ LED ม่วง "มืดเกินไป"
- กล้องต้องอยู่ตรงหน้าคนขับ ถ้าติดเยื้องมากระบบจะดูตาได้ไม่แม่น
- ค่า `IRIS_DARK_MIN` และ `SMILE_RATIO` ทดสอบกับคนไม่กี่คน ควรทดสอบเพิ่ม

**งานต่อไป**
- [ ] ให้แอปเปิดเองอัตโนมัติเมื่อบอร์ดเปิด
- [ ] ส่งเหตุการณ์เตือนขึ้นเซิร์ฟเวอร์ (คิวออฟไลน์ SQLite) ผ่านฮอตสปอตมือถือคนขับ
- [ ] เว็บสำหรับคนขับ (ประวัติความง่วง, เตือนพัก) และบริษัท (แดชบอร์ดรถทั้งหมด, แจ้งเตือน SMS/LINE)
- [ ] เพิ่มรหัสผ่านให้หน้าเว็บก่อนใช้งานจริง
- [ ] ฝึกโมเดลตาเปิด/ปิดเองด้วยภาพจากกล้องตัวนี้ (แม่นกว่าโมเดลสาธารณะ)

## 11. อัปเดต 20 พ.ย. 2026

**หน้าเว็บ / แผนที่**
- ซูมแผนที่ได้ถึงระดับ 18 (ไฟล์แผนที่มีข้อมูลถึงซูม 14 → ยืดใช้ต่อ, `maxDataZoom`)
- `assets/both.html` ภาพสด (ซ้าย) + แผนที่ (ขวา) ในจอเดียว: `http://antims.local:7000/both.html`
- เส้นทางไปจุดพักวาดตามถนนจริง (เส้นสีน้ำเงินแบบ Google Maps) จาก OSRM `/route`
- ปุ่ม 🧭 นำทาง: ตอนยังไม่มี GPS จะเปิด Google Maps จากตำแหน่งทดสอบเดียวกัน (เทียบเส้นทางได้)
- เมื่อรู้ทิศรถ (GPS ≥ 15 กม./ชม. หรือตำแหน่งทดสอบที่ใส่ `course`):
  - เส้นทางต้องออกตัวตามทิศที่รถวิ่ง (OSRM `bearings`, ±45°) → ปั๊มฝั่งตรงข้ามถนนที่มีเกาะกลางคิดระยะกลับรถจริง
  - ปั๊มฝั่งตรงข้าม (ขวามือ, ไทยขับชิดซ้าย) นับว่าไกลขึ้น 1 กม. → เลือกปั๊มฝั่งเดียวกันก่อน
  - หน้าเว็บบอก "ฝั่งเดียวกัน" / "ฝั่งตรงข้าม (ต้องกลับรถ)"
- `POST /api/test_location` รับ `{"lat", "lon", "course"}` (course = ทิศรถ องศา, 0 = เหนือ)

**ผลเทียบกับ Google Maps (ปั๊มที่ใกล้ที่สุด 25 จุดทั่วประเทศ)**: ใกล้เคียง 18/25 · ต่างมาก 6
สาเหตุ: ข้อมูลถนนบนบอร์ดเป็นแบบ `lighter` (ไม่มีซอย/ถนนบริการ/ถนนคู่ขนาน) เพราะ RAM ไม่พอ
การสร้างแบบ `light` (มีซอย) ด้วย 1 เธรดยังไม่พอ (osrm-extract ใช้ ~2.5 GB แล้วโดนตัด)

**ทางแก้ข้อมูลถนนที่ยังไม่ได้ทำ** (เลือกอย่างใดอย่างหนึ่ง)
1. กรองไฟล์แผนที่ให้เหลือแค่ถนน (`osmium tags-filter ... w/highway r/type=restriction`) แล้ว `osrm_build.sh full`
   (ต้องมีที่ว่างบนดิสก์ระบบ `/` ให้ docker ดึง image)
2. เพิ่ม swap 4 GB: `sudo bash ~/osm/add_swap.sh` (ไฟล์อยู่ที่ `/home/arduino/swapfile`)

**⚠️ ปัญหาที่ค้าง**
- ดิสก์ระบบ `/` ของบอร์ดเต็ม 100% จากไฟล์ `/home/swapfile` (2.9 GB, สคริปต์ swap เวอร์ชันแรกวางผิดที่)
  ลบด้วย `ssh -t arduino@<IP บอร์ด> "sudo rm -f /home/swapfile"`
- กล้อง USB หลุดเองหลายครั้ง (error -71 = ไฟ/สัญญาณ) → ใช้ hub ที่มีไฟเลี้ยงของตัวเอง, ถอดลำโพง USB
- หน้าดูสด (พอร์ต 7000) ยังไม่มีรหัสผ่าน ใครต่อ Wi‑Fi เดียวกันก็ดูวิดีโอได้
